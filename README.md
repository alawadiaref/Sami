# METRIQUE — متجر الساعات الفاخرة

موقع تجارة إلكترونية مبني بـ Next.js (React) + TypeScript + Tailwind، مبني على التصميم المعتمد (نموذج 2 — الأناقة العصرية، كحلي وأزرق).

## التشغيل محليًا

```bash
npm install
npm run dev     # وضع التطوير: http://localhost:3000
# أو
npm run build && npm start   # وضع الإنتاج
```

> ملاحظة: ملفات `data/admins.json` و`data/customers.json` (فيها بيانات دخول حقيقية) غير مرفوعة على GitHub عمدًا — الموقع يستخدم `data/admins.example.json` تلقائيًا كحساب مالك افتراضي (admin / changeme123) إلى أن تضيف أو تعدّل مشرفًا من صفحة "إدارة المشرفين"، وحينها يُنشئ الملف الحقيقي بنفسه. تقدر أيضًا تنسخ `admins.example.json` إلى `admins.json` يدويًا وتغيّر الاسم/كلمة المرور مباشرة.

## لوحة التحكم (Admin)

الرابط: `/admin`

**حساب المالك الافتراضي:**
- الاسم: `admin`
- كلمة المرور: `changeme123`

غيّرها من ملف `data/admins.json` مباشرة (أو أنشئ حساب مالك جديد وامسح القديم).

**نظام صلاحيات حقيقي متعدد المستخدمين:**
- **المالك**: صلاحيات كاملة تلقائيًا على كل الأقسام، ولا يمكن حذفه أو تقييده.
- من صفحة **إدارة المشرفين** (`/admin/team`، للمالك فقط افتراضيًا)، ينشئ المالك حسابات مشرفين جدد ويحدد بالضبط أي أقسام يصل لها كل واحد: المنتجات، الطلبات، العروض والتخفيضات، المظهر والألوان، الإحصائيات، إدارة المشرفين، الإعدادات.
- التقييد فعلي على مستوى الصفحة والـ API، مو مجرد إخفاء رابط — مشرف بدون صلاحية "الطلبات" مثلاً ما يقدر يفتح `/admin/orders` حتى لو كتب الرابط يدويًا.

**الأقسام المتاحة:**
- لوحة القيادة: إحصائيات فورية (حسب صلاحية المستخدم) — عدد الطلبات، المنتجات، الإيرادات، إجمالي الزيارات وزيارات اليوم، رسم بياني لآخر 7 أيام، وأكثر/أقل 3 منتجات زيارة.
- المنتجات: إضافة/تعديل/حذف.
- الطلبات: تغيير الحالة (بانتظار الدفع، قيد التجهيز، تم الشحن...).
- العروض والتخفيضات: تفعيل خصم بنسبة مئوية على أي منتج مع اسم عرض، ويظهر فورًا على الموقع مع شارة وسعر مشطوب.
- المظهر والألوان: تُطبَّق على الموقع فورًا.
- **محتوى الموقع** (`/admin/content`): تحكم كامل بنصوص الموقع وصوره —
  - أول صورتين في الموقع (خلفية الواجهة الرئيسية وصورة قسم المجموعة الأولى).
  - نصوص أقسام المجموعات (الوسم/العنوان/الوصف) وشريط الإحصائيات الأربعة.
  - شريط صور بالصفحة الرئيسية: اختيار المنتجات التي تظهر فيه، اسمه، سرعة تبديل الصور، وطريقة الانتقال (تلاشي/انزلاق).
  - حسابات التواصل الاجتماعي: إضافة/حذف أي عدد من الحسابات (واتساب، سناب شات، إنستقرام، إكس/تويتر) وتظهر تلقائيًا في تذييل الموقع وصفحة "تواصل معنا".
  - سياسة الشحن وسياسة الاستبدال والاسترجاع (نص حر) — تظهر في `/policies/shipping` و`/policies/returns`.
  - صور كل منتج وإعدادات شريط صوره الخاص (الاسم، سرعة التبديل، طريقة الانتقال) تُدار من صفحة **المنتجات** نفسها (زر "الصور والمعرض" أمام كل منتج).
- الإعدادات: حالة الربط مع بوابات الدفع والتوصيل.

> ملاحظة أمان: كلمات المرور محفوظة كنص عادي في `data/admins.json` (ونفس الشيء لحسابات العملاء في `data/customers.json`) — مقبول للتجربة، لكن قبل الإطلاق الفعلي لازم تُشفّر (bcrypt أو ما شابه) قبل ما توصل بيانات حقيقية. نقطة التعديل الوحيدة هي `src/lib/auth.ts` و`src/lib/admins.ts` (للأدمن) و`src/lib/customer-auth.ts` و`src/lib/customers.ts` (للعملاء).

## حساب العميل (تسجيل الدخول في المتجر)

الرابط: `/account`

صفحة تسجيل دخول/إنشاء حساب للعملاء (منفصلة تمامًا عن حساب المالك/الأدمن) بتصميم فاخر يتماشى مع هوية المتجر — بريد إلكتروني وكلمة مرور، مع تبويب لإنشاء حساب جديد (الاسم، البريد، الجوال، المدينة، العنوان التفصيلي، كلمة المرور). الجلسة محفوظة بكوكي منفصل (`customer_session`) عن جلسة الأدمن، والبيانات في `data/customers.json`. عند تسجيل الدخول تُستخدم بيانات العميل المحفوظة (الاسم والجوال) لتعبئة صفحة إتمام الطلب تلقائيًا.

## السلة والدفع

- **السلة** (`/cart`): تُحفظ في متصفح العميل (localStorage) وتُزامن تلقائيًا مع الخادم لأغراض تتبع السلات المتروكة. عداد صغير يظهر فوق أيقونة السلة بعدد القطع. تعرض صفحة السلة أيضًا قسم "أكمل طلبك" باقتراحات من نفس تصنيف المنتجات الموجودة في السلة والتي لم تُضَف بعد.
- **الدفع** (`/checkout`): نموذج بسيط (الاسم، الجوال، طريقة الدفع) يُنشئ الطلب عبر بوابات الدفع الموضحة أدناه، ثم صفحة تأكيد طلب (`/order/[id]`) تعرض ملخص الطلب (وبيانات التحويل البنكي إن كانت طريقة الدفع تحويل بنكي).
- **إشعارات السلات المتروكة**: مهمة مجدولة (`/api/cron/abandoned-carts`، مضبوطة في `vercel.json` لتعمل كل ساعة عبر Vercel Cron) تفحص السلات غير المكتملة منذ أكثر من ساعة وترسل تذكيرًا فعليًا عبر البريد الإلكتروني والواتساب (أو تُسجّله فقط في وضع تجريبي حتى تتوفر مفاتيح API — انظر `src/lib/notifications/`). لحماية الرابط في الإنتاج، أضف `CRON_SECRET` في متغيرات البيئة.

## مساعد الدردشة (الدعم الفني)

فقاعة دردشة عائمة تظهر في كل صفحات المتجر (ما عدا لوحة التحكم). تجيب حاليًا من قاعدة معرفة محلية مبنية من سياسة الشحن/الاسترجاع ووسائل التواصل — دون أي اتصال خارجي أو تكلفة. بمجرد إضافة `CHATBOT_API_KEY`، يتحول الرد تلقائيًا لنموذج ذكاء اصطناعي حقيقي (الكود جاهز ومُعلّق في `src/app/api/chatbot/route.ts`) دون الحاجة لتعديل أي شيء آخر.

## الحالة الحالية لكل جزء

| الجزء | الحالة |
|---|---|
| الواجهة الرئيسية (هيرو الساعة المتفككة/المتجمّعة، الأقسام، المنتجات) | ✅ فعلي وجاهز |
| المظهر والألوان القابلة للتعديل من لوحة التحكم | ✅ فعلي (محفوظة في `data/theme.json`) |
| المنتجات (عرض + إدارة) | ✅ فعلي (محفوظة في `data/products.json`) |
| الطلبات وتتبع حالتها | ✅ فعلي (محفوظة في `data/orders.json`) |
| الدفع عبر تابي (Tabby) | 🟡 هيكلة جاهزة، تعمل بوضع تجريبي حتى تتوفر مفاتيح API — `src/lib/payments/tabby.ts` |
| الدفع عبر تمارا (Tamara) | 🟡 نفس الشيء — `src/lib/payments/tamara.ts` |
| الدفع بالبطاقة (مدى/فيزا/ماستركارد) | 🟡 هيكلة جاهزة لأي بوابة (يُفضّل Moyasar لدعم مدى) — `src/lib/payments/card.ts` |
| التحويل البنكي | ✅ فعلي جزئيًا: يعرض بيانات الحساب ويحتاج تأكيد يدوي من الأدمن — `src/lib/payments/bank-transfer.ts` |
| خدمة التوصيل | 🟡 هيكلة جاهزة بوضع تجريبي — `src/lib/delivery.ts` |
| حساب العميل (تسجيل دخول/إنشاء حساب في المتجر) | ✅ فعلي (محفوظ في `data/customers.json`) — `/account` |
| السلة والدفع وتأكيد الطلب | ✅ فعلي — `/cart`, `/checkout`, `/order/[id]` |
| إشعارات السلات المتروكة (بريد/واتساب) | 🟡 هيكلة جاهزة، تعمل بوضع تجريبي (تُسجَّل في السجلات) حتى تتوفر مفاتيح API — `src/lib/notifications/` |
| محتوى الموقع القابل للتعديل بالكامل من لوحة التحكم | ✅ فعلي (محفوظ في `data/content.json`) — `/admin/content` |
| مساعد الدردشة (الدعم الفني) | 🟡 يعمل فعليًا بقاعدة معرفة محلية؛ يتحول لنموذج ذكاء اصطناعي حقيقي عند إضافة `CHATBOT_API_KEY` |
| سياسة الشحن والاستبدال/الاسترجاع | ✅ فعلي، نص قابل للتعديل من لوحة التحكم — `/policies/shipping`, `/policies/returns` |

**"وضع تجريبي" يعني:** كل شيء يعمل الآن بالكامل من ناحية تجربة المستخدم (checkout كامل، تتبع طلب، إلخ) لكن بدون اتصال حقيقي بأي بوابة خارجية. بمجرد توفر حسابات تابي/تمارا/بوابة البطاقات/شركة التوصيل، تُضاف مفاتيحها كمتغيرات بيئة (`.env.local`) بنفس الأسماء الموجودة في كل ملف، ويتحول العمل تلقائيًا للوضع الحقيقي دون تعديل بقية الموقع.

## متغيرات البيئة (`.env.local`)

```
ADMIN_SESSION_SECRET=      # نص عشوائي طويل لتوقيع جلسة الأدمن
CUSTOMER_SESSION_SECRET=   # نص عشوائي طويل لتوقيع جلسة العميل

TABBY_SECRET_KEY=
TAMARA_API_TOKEN=
CARD_GATEWAY_SECRET_KEY=
DELIVERY_PROVIDER_API_KEY=

# إشعارات السلات المتروكة — بدونها تُسجَّل الإشعارات فقط في السجلات (وضع تجريبي)
EMAIL_API_KEY=
EMAIL_FROM=
WHATSAPP_API_TOKEN=
WHATSAPP_PHONE_ID=
CRON_SECRET=               # يحمي رابط /api/cron/abandoned-carts في الإنتاج

# مساعد الدردشة — بدونه يجيب المساعد من قاعدة معرفة محلية فقط
CHATBOT_API_KEY=
```

> ملاحظة: جدولة مهمة السلات المتروكة (`vercel.json`) تعمل تلقائيًا بعد الرفع على Vercel. الخطة المجانية (Hobby) في Vercel قد تُقيّد تكرار Cron Jobs (غالبًا مرة يوميًا كحد أقصى) — إذا لم تعمل بالتكرار المطلوب (كل ساعة)، فعّل خطة Pro أو استدعِ الرابط يدويًا/عبر خدمة جدولة خارجية.

## الخطوات التالية المقترحة

1. اسم المتجر النهائي والشعار (حاليًا METRIQUE كاسم مبدئي من نماذج التصميم — عدّله من لوحة التحكم ← المظهر والألوان).
2. رفع صور المنتجات الحقيقية، وأول صورتين في الموقع، من لوحة التحكم (المنتجات، ومحتوى الموقع).
3. فتح حسابات تابي وتمارا وبوابة البطاقات وربط مفاتيحها.
4. اختيار شركة التوصيل الفعلية وربط API الخاص بها.
5. ربط مزود بريد إلكتروني حقيقي وواتساب بزنس لتفعيل إشعارات السلات المتروكة فعليًا (`EMAIL_API_KEY`، `WHATSAPP_API_TOKEN`).
6. ربط مفتاح نموذج ذكاء اصطناعي حقيقي (`CHATBOT_API_KEY`) ليجيب مساعد الدردشة بشكل مفتوح بدل الأجوبة الجاهزة.
7. **مهم قبل الاستضافة الحقيقية**: قاعدة البيانات الحالية عبارة عن ملفات JSON (`data/*.json`) تُكتب مباشرة على القرص — هذا يعمل بشكل ممتاز محليًا وأثناء التطوير، لكن معظم منصات الاستضافة الجادة (مثل Vercel) تشغّل الخادم على بيئة بدون تخزين دائم، فأي تعديل (سعر، طلب، سلة، محتوى) قد لا يُحفظ بين الطلبات. لذلك، قبل الانتقال من "تجربة الزبون" إلى موقع حقيقي بمستخدمين حقيقيين، يجب الانتقال إلى قاعدة بيانات حقيقية (Postgres, MongoDB, إلخ) — نمط الكود الحالي (`lib/*.ts` بدوال get/save بسيطة) مصمم خصيصًا ليسهل استبداله لاحقًا دون تغيير بقية الموقع.
